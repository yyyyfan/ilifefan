# 048 抽签页

## 目标

应援站加一页「抽签」：从现有曲库里抽一首歌，或从成员里抽一位推。抽取先有大约两秒的摇签，再展开一张横线签纸：拍立得式图片、圆章和花瓣。结果可以存成 9:16 分享图。记录只留在浏览器里，不设每天只能抽一次。

## 范围

- 新页面 `draw.html`（`data-page=draw`）。导航在歌曲旁边加 `DRAW / 抽签`。
- `app.js` 渲染两种模式、本地记录、分享图；`style.css` 用现有粉色变量。`_headers` 给 `/draw` 加 `no-cache`。
- `db/export.py` 按现有机制刷新 `?v=` 与 `data/version.json`。不改 sqlite，不手改 `data/*.json` 的内容，不上传新图。
- 不做账号、后端、每日锁死、运势文案，也不搬参考站的插画和水色配色。

## 数据来源

不新增事实。抽歌用已导出的 `data/songs.json`（封面优先级与歌曲列表相同）。抽推用 `data/members.json` 和 `latestPhoto`（与成员卡片同一张最近公式图）。日期按日本时间。

## 验收标准

- [ ] 打开 `draw.html`，导航高亮 `DRAW / 抽签`。默认「抽歌」，可切到「抽推」。待机是居中窄栏：大标题、说明、大圆角按钮，以及抽歌 / 抽推 / 分享三张说明卡。
- [ ] 抽歌筛选：全部 / 团体曲（`member` 为空）/ 个人曲（`member` 有值）。结果在横线签纸上，有拍立得式封面、日文歌名、假名、时长、作品，链接 `songs.html?s=<id>`。
- [ ] 抽推默认只有现役；打开「含前成员」后池子包含前成员。结果有最近公式图、应援色条、日文名、假名、口号（若有），链接 `members.html?m=`。
- [ ] 可以连续再抽。当天该模式的第一次抽，圆章写「今日首抽」。每种模式最近记录最多 20 条，排成软卡片格子，存在 `localStorage` 键 `ilifefan-draw-v1`。
- [ ] 抽取先摇大约两秒，再弹出圆章并撒花瓣。系统开启「减少动态效果」时直接出结果，不做动画、不撒花瓣。下标用 `crypto.getRandomValues`。
- [ ] 「保存卡片」生成 900×1600 的 PNG。浏览器能用文件分享时走系统分享，否则下载。取消分享不会再下载一遍。可以导出 / 导入 JSON。
- [ ] 桌面和手机宽度都没有整页横向滚动，图片不裁切。
- [ ] `python3 db/export.py --check` 通过。
