# 051 界面文案三语补齐（中 / 日 / 英）

执行者：CodeBuddy（本机会话）。分支：main（沿用本会话前几个任务的做法）。

## 目标

049/050 给抽签页做了中日英三语，但**主站 8 个页面（首页 / 成员 / 歌曲 / 公演 / 场地 / 日程 / 时期 / 图库）几乎全是写死的中文**：
切到日文或英文，导航、页脚、语言菜单是翻译过的，但统计条、筛选器、表头、详情字段名、空状态、提示语全是中文。
这个任务把「界面文案」全部收进一张字典，数据本身（成员名、歌名、公演名、备注、推文原文、应援色）保持原文不动。

## 范围

改 `app.js`（唯一的前端脚本）与 `docs/AGENTS` 规范；不动 `db/ilife.sqlite`、不动 `data/*.json` 的内容。

- 新增 `UI` 字典：键是简体中文原文，值是 `[日本語, English]`；中文直接返回键本身，所以不用维护第三份。
- 新增 `i18n(s, vars)`：取当前语言的文案，支持 `{n}` 这类占位符；缺 key 时回落中文。
- 新增 `pname(pref)`：库里 `venues.pref` / `lives.pref` 存的是中文简称（`东京`、`冲绳`），显示时按语言换成 `東京都` / `Tokyo`。
- 新增 `liveType(t)`：公演类型（`ワンマン` / `対バン` …）在库里是日文枚举值，中文页显示「单独公演 / 对盘公演」，英文页显示 `Solo show / Shared bill`。
- 顺带加了 `?lang=zh|ja|en`：可以直接分享指定语言的链接，也方便回归测试。

**不做的**：数据正文（公演名、歌曲名、成员名、note 备注、推文原文、打歌服名、应援色写法）一律保留原文；
抽签页（`draw.html`）的文案 049/050 已经三语化，这次只在它漏掉的标题处对齐。
